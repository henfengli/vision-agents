# 需求背景

本文说明这套 agent 平台要解决什么问题、面对的是什么现场、有哪些约束。怎么实现见[设计文档](设计文档.md)，怎么装见[部署指南](部署指南.md)。

master 上是**独立机器 + 本机代码副本**的方案：平台装在一台机器上，为每个服务、每个环境放一份代码和配置，给 agent 参考和调试。
`colocated` 分支是后来改成的同机部署方案（agent 装在线上主机上，直接面对线上现场），见第 6 节。

## 1. 要解决的问题

组里几个人维护 Vision 的几套业务服务。有几类工作要同时看代码、配置和库才能做，又经常重复：

- 回答数据口径问题：报表上的某个数来自哪几张表、怎么算的；
- Dagster 资产物化失败时查根因：是上游延迟级联、数据问题还是代码问题；
- 部署之后检查报表页面和接口是否正常；
- 每天巡检报表数据的新鲜度和线上页面。

希望由一套 agent 服务来做这些事：业务项目和组里的人随时能问；固定的检查按时自己跑，结论直接推到钉钉群。

## 3. 怎么用

1. **项目调 agent**：业务项目通过 HTTP API 或 Python SDK 请 agent 做事，例如问口径、分析一次报错、跑一次检查。
2. **任务自己跑**：定时（每天巡检 prod 和 test）、事件（Dagster 运行失败、GitLab 部署完成）或在控制台点一下触发，
   无人值守跑完，结果投递到钉钉或回调地址。
3. **在控制台对话**：组里的人直接提问，过程（模型调用、工具调用）实时可见，会话能接着问。

## 4. 需求

### 4.1 agent 要能碰到项目本身

- 读项目的代码；
- 读对应环境的配置文件（密钥打码）；
- 查只读库（目前是 ClickHouse，以后可能有 MySQL、Doris、MongoDB）；
- 在该环境的项目 Python 里跑项目代码：import 项目模块，调项目自己的口径函数、ORM、Dagster 资产；
- 用 Dagster 的 MCP 工具只读查询线上 Dagster 的运行记录；
- 需要长驻时按环境起项目进程（带租约，用完停）。

### 4.2 部署

- 一套统一的 agent 服务，供这些服务共同使用，装在一台机器上。
- 用一个新建的独立普通用户运行，平台和它起的业务进程都是这个用户（systemd --user，基本不用 root）。
- 这台机器上为每个服务、每个环境放一份代码（`~/svc/<服务>/code/<环境>`，都跟踪 master；发现远端有新提交由平台对齐、按变更装依赖），
  每个项目一个 conda 环境（各环境共用），每个环境一份配置文件（`~/svc/<服务>/conf/<环境>`，可以在控制台改）。
- 线上实例不碰：平台机器上的副本只给 agent 参考和调试。

### 4.3 安全

- 各环境配置里的库账号都是只读的。
- agent 的 `bash` 和 `py` 文件系统只读（工作目录除外）；拉代码、装依赖、改配置由平台进程做，不由 agent 做。
- bash 里看不到配置文件和密钥，配置只能经工具读打码后的版本。
- 不分权限，不做审批。用户是组里几个人，分工明确，都在内网；谁做了什么按 API 密钥名记在运行台账里。

### 4.4 模型

- Kimi（月之暗面开放平台，OpenAI 兼容），模型 `kimi-k2.7-code`，可以多把 key 轮换。
- 账号并发 3。不按分钟限速：一次响应回来，下一步立刻发请求。
- 开发时用的试用 key 限并发 1、每分钟 3 次，只用来测功能，不是线上额度。

### 4.5 其他约束

- 单部署：一套 agent 服务操作所有项目的所有环境。
- 必需的外部依赖只有 PostgreSQL；不用容器，跑在平台用户的 systemd --user 里。
- 没有用户体系，身份就是 API 密钥。
- 钉钉只发不收。
- 服务、角色、任务的定义在控制台改，存库、带版本，改完就生效。
- 项目还在定架构阶段，没有发过正式版。

## 5. 不做什么

- 不碰线上：线上的发布、依赖、配置、进程照旧走项目自己的流程。
- 不做用户、权限和审批。

## 6. 后来的调整（`colocated` 分支）

这套方案用下来的问题：

- 本机副本和线上总有差别，排查线上问题时看的不是线上那份；
- 配置换成只读账号之后，副本里的 Dagster 很多地方跑不起来；
- 看不到线上的日志、主机状况和 nginx；
- 要单独建用户、配权限，还要维护代码同步和进程启停。

所以 `colocated` 分支改成同机部署：agent 服务装在线上主机上、和项目同一个用户，生产、测试各自的 agent 服务共用一套控制台和一个库，
平台不再管代码和进程，只保证数据库安全（只读账号）和线上机器的内存安全。详见该分支的 `docs/需求背景.md`。
