# 部署指南

面向内网主机的完整部署手册。部署形态：**主机 + systemd，无容器**。

平台一个进程内包含三件东西：FastAPI 接入层（`/v1` API + Viewer 页面）、
Temporal worker（编排执行）、agent 运行时。外部依赖只有 PostgreSQL 与
Temporal server（随附 systemd unit，可同机跑）。

---

## 1. 前置条件

| 项 | 要求 | 说明 |
|---|---|---|
| OS | Linux（x86_64），systemd | 脚本与 unit 按 RHEL/Debian 系通用写法 |
| Python | ≥ 3.11 | `pyproject.toml` 的 `requires-python` |
| PostgreSQL | ≥ 14，同机或可达 | 需 **pg_trgm**（PG13+ 为 trusted extension，库 owner 可建）与 **pgvector**（需超级用户建，见 §3.2） |
| bubblewrap | `bwrap` 命令可用 | **必装**。缺失则 bash/run_code 退化为无隔离执行，且 run 内后台进程失去清理保证（install.sh 会警告） |
| Temporal CLI | `/usr/local/bin/temporal` | 随附 `temporal-server.service` 用它起开发模式服务端（SQLite 持久层）；已有独立 Temporal 集群则不需要 |
| 网络可达 | 内部模型 API、钉钉中继、PG | 出网访问全部收口为薄工具，agent 沙箱默认断网 |
| 可选 | Node.js / uv | 仅当启用 browser（@playwright/mcp）/ datahub MCP 服务器时需要 |
| 可选 | Langfuse、Grafana | 观测与主机监控，不配则对应能力自动关闭 |

## 2. 资源布局（安装后）

```
/opt/agent-platform/        代码包（root 所有，agent-svc 只读）
├── venv/                   虚拟环境
├── src/ conf/ mcp_servers/ pyproject.toml
/etc/agent-platform/
└── secrets.env             密钥（640 root:agent-svc，不进仓库/压缩包）
/var/lib/agent-platform/
├── scratch/                agent 工作区（沙箱内唯一可写目录）
└── assets/                 任务资产库（save_asset 收编的文件载体，含 .revs 留档）
/var/lib/temporal/           Temporal SQLite 持久层
/var/log/agent-platform/     应用日志目录
```

systemd units：`agent-platform.service`（主服务，127.0.0.1:8100）、
`temporal-server.service`（127.0.0.1:7233 + UI 8080）。

## 3. 首次部署

### 3.1 准备数据库

```sql
-- 以 PG 超级用户执行
CREATE USER agent PASSWORD '<强密码>';
CREATE DATABASE agent_platform OWNER agent;
\c agent_platform
CREATE EXTENSION IF NOT EXISTS vector;   -- pgvector：必须超级用户预建
CREATE EXTENSION IF NOT EXISTS pg_trgm;  -- trusted，owner 即可；预建更稳
```

两张表结构由服务启动时幂等自建（`CREATE TABLE IF NOT EXISTS` + 增量
`ALTER`，无需手工迁移脚本）。但 `vector` 扩展建不了时应用只会记 warning
并退化为纯文本检索（trgm），不会启动失败——**想用语义召回就必须预建**。

### 3.2 检查环境配置

编辑 `conf/env/prod.yaml`（部署前在仓库里改好再推）：

- `model.url` / `model.name`：内部 OpenAI 兼容模型地址与模型名
- `dingtalk_relay_url`：钉钉中继地址
- `viewer_base_url`：Viewer 的外网访问地址（钉钉审批卡片 deep-link 用它）
- `target_envs` / `default_target_env`：单部署多目标环境；不配 = 单环境
- `approvals.enabled: true`：生产建议开（危险命令强制人工审批）
- `langfuse.enabled` / `grafana:` / `mcp_servers:`：按需
- `conf/domains/<域>/`：业务域包（`domain.yaml` 的 code_paths/hosts、
  `tasks.yaml` 种子任务）

### 3.3 执行安装

```bash
sudo bash deploy/install.sh prod
```

脚本动作：建 `agent-svc` 低权限用户 → 拷代码（src/conf/mcp_servers/
pyproject.toml）到 /opt → 建 venv 并 `pip install /opt/agent-platform`
→ 检查 bwrap 与 secrets.env → 装两个 systemd unit 并启动。

此时 secrets.env 还没放，脚本会打印警告、服务起不来——**属预期**，下一步
放好后重启即可。

依赖安装走 PyPI——内网不通外网时先配镜像：

```bash
sudo /opt/agent-platform/venv/bin/pip config set global.index-url <内网镜像>
# 或在 install.sh 前设置 PIP_INDEX_URL 环境变量
```

### 3.4 放置密钥并重启

```bash
sudo tee /etc/agent-platform/secrets.env > /dev/null <<'EOF'
MODEL_TOKEN_A=sk-...            # 内部模型 API token（model.tokens[0]）
MODEL_TOKEN_B=sk-...            # 第二个 token（并发池轮换；只有一个就填同一个）
AGENT_DB_PASSWORD=...           # 3.1 的 PG 密码
DINGTALK_ACCESS_TOKEN=...       # 钉钉机器人 token（中继用）
AGENT_BEARER_TOKEN=...          # 平台固定 bearer：/v1 鉴权 + Viewer 登录口令
LANGFUSE_PUBLIC_KEY=pk-...      # 可选：启用 langfuse 时必填
LANGFUSE_SECRET_KEY=sk-...      # 可选
EOF
sudo chown root:agent-svc /etc/agent-platform/secrets.env
sudo chmod 640 /etc/agent-platform/secrets.env
sudo systemctl restart agent-platform
```

配置里 `${VAR}` 从 secrets.env 插值，**未设置则启动即报错**（配置问题
暴露于启动期，不带病运行）。

### 3.5 验证

```bash
systemctl status agent-platform temporal-server --no-pager
curl -s http://127.0.0.1:8100/health
# {"status":"ok","env":"prod","version":"5.16.0","target_envs":[...]}

journalctl -u agent-platform -n 100 --no-pager   # 不应有 ERROR
```

首次启动会自动做三件事：建全库 12 张表、种子角色入库
（`seed_if_empty`，仅空库时）、同步 Temporal Schedules。

浏览器访问 Viewer（经反向代理，见 §4）：打开 `/login`，粘贴
`AGENT_BEARER_TOKEN` 登录（httponly cookie；内网无用户体系，口令即身份）。

发一个冒烟 run 验证全链路（SDK 交互式 CLI）：

```bash
pip install ./sdk    # 或任意可达机器上 pip install /opt/agent-platform/sdk
export AGENT_BASE_URL=http://127.0.0.1:8100 AGENT_TOKEN=<AGENT_BEARER_TOKEN>
agent-chat --server board --role data_searcher --env test
# [session: ...] > ping：回复 ok 即可
```

## 4. 反向代理与外部访问

主服务只监听 `127.0.0.1:8100`（刻意不暴露）。生产需要反代给内网用户：

```nginx
server {
    listen 443 ssl;
    server_name agent-viewer.prod.internal;   # 与 viewer_base_url 一致
    # ssl_certificate / ssl_certificate_key ...
    location / {
        proxy_pass http://127.0.0.1:8100;
        proxy_set_header Host $host;
        proxy_set_header X-Forwarded-For $remote_addr;
        proxy_read_timeout 3600s;             # SSE 长连接（/v1/chat/stream）
        proxy_buffering off;                  # SSE 需要实时冲刷
    }
}
```

要点：`viewer_base_url` 必须与最终访问地址一致（钉钉审批卡片/通知里的
链接用它拼）；SSE 端点要求反代不关缓冲、超时拉长。

Temporal UI（8080）只用于排障，不建议对外；需要时单独加访问控制。

## 5. 升级与回滚

### 5.1 升级

```bash
git pull                            # 或替换为新包
sudo bash deploy/install.sh prod    # 幂等：重拷代码 + 重装 venv + 重启
```

- DB schema 变更随启动自动应用（幂等 DDL），无需手工迁移
- 角色/任务/策略定义在库里不在包里，升级不动定义；种子只在空库时写入
- 内容历史（asset_history/knowledge_history）与定义历史全在 PG，升级保留

### 5.2 回滚

```bash
git checkout <上一个 tag/commit>
sudo bash deploy/install.sh prod
```

schema 只增不减（新表/新列对旧代码无害），代码回滚安全。数据层面的
"回滚"走应用内能力：定义版本 rollback API、知识/资产内容历史 restore、
资产文件 .revs 回滚——都不需要动 DB。

## 6. 备份与恢复

需要备份的只有两类：

| 数据 | 位置 | 方式 |
|---|---|---|
| PG 全库（台账/定义/知识/案例/资产元数据/全部历史） | `agent_platform` 库 | 定期 `pg_dump -Fc agent_platform` |
| 资产文件载体（含 .revs 留档） | `/var/lib/agent-platform/assets/` | 文件级备份（rsync/对象存储） |

不需要备份：`scratch/`（临时工作区）、`/var/lib/temporal/`（执行历史，
丢了只影响排障不影响状态——真正的状态在 PG）、代码包（仓库里有）。

恢复：装好 PG → 恢复 dump → 装代码（install.sh）→ 恢复 assets 目录 →
启动。表结构与 dump 版本不一致时启动自动补齐。

## 7. 日常运维

```bash
journalctl -u agent-platform -f          # 应用日志
curl -s 127.0.0.1:8100/health            # 存活 + 版本 + 目标环境
systemctl restart agent-platform         # 重启（定义/配置改动建议用管理页，热生效）
```

- **配置改动**：改 `/opt/agent-platform/conf/` 后 `systemctl restart
  agent-platform`（配置只在启动时读；但角色/任务/策略是 DB 热生效，不用重启）
- **进程清理保证**：run 内起的任何进程（含后台服务）在 run 结束时被
  PID namespace 整体回收（bwrap `--unshare-pid --as-pid-1`）；若日志出现
  bwrap 缺失告警，沙箱与清理保证同时失效，应立即安装
- **沙箱写边界**：agent 只能写 `scratch/`；资产库写入只走 save_asset
  工具（宿主侧，可审计）

## 8. 故障排查

| 现象 | 排查 |
|---|---|
| 启动即退出 | `journalctl -u agent-platform -n 200`：多半是 secrets.env 缺变量（`${VAR}` 插值报错）或 PG 连不上 |
| 日志有 "迁移跳过 ... vector" | pgvector 未预建：以超级用户 `CREATE EXTENSION vector`，重启服务；此前语义召回处于 trgm 退化态 |
| 日志告警 bwrap | `apt-get install -y bubblewrap`（或 yum 系等价），不装则沙箱失效 |
| run 全部卡住不动 | `temporal server` 未起：`systemctl status temporal-server`；`temporal workflow list --address 127.0.0.1:7233` 验证 |
| Viewer 登录后跳回 /login | cookie 被拦：确认经反代访问且反代不改写 Set-Cookie；http 站点 Secure cookie 策略问题则用 https |
| 钉钉收不到审批卡片 | 检查 `dingtalk_relay_url` 可达性与 `DINGTALK_ACCESS_TOKEN`；卡片 deep-link 域名 = `viewer_base_url` |
| 模型调用 401/超时 | `MODEL_TOKEN_*` 失效或 `model.url` 不通；token 池并发上限见 `model.max_concurrency` |
| SSE 聊天首字节慢/断开 | 反代缓冲或超时：`proxy_buffering off` + 拉长 `proxy_read_timeout` |

## 9. 安全基线（部署后自查）

- [ ] `secrets.env` 权限 640、root:agent-svc，未进任何仓库/压缩包/提交
- [ ] 服务以 `agent-svc` 低权限用户运行；`/opt/agent-platform` root 所有只读
- [ ] systemd 加固生效：`ProtectSystem=strict` + `NoNewPrivileges` +
      `PrivateTmp`（unit 已带，勿删）
- [ ] 8100 只绑 127.0.0.1；外部访问一律过反代
- [ ] `approvals.enabled: true`（生产）；危险模式正则按需扩充
- [ ] bwrap 已安装（沙箱 = 全盘只读 + 仅 scratch 可写 + 默认断网）
- [ ] 生产 `default_target_env` 指向 test——生产操作必须显式声明 env
- [ ] 模型 API token 泄露应急：轮换后只改 secrets.env + 重启即可
