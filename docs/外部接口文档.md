# 外部接口文档（/v1）

平台全部对外 HTTP 接口。调用方：业务系统、脚本、AI 运维、SDK
（`sdk/` 就是这套接口的薄封装，见 `docs/SDK开发指南.md`）。
Viewer 页面也只是这套 API 的一个客户端。

## 通用约定

### Base URL 与鉴权

- Base URL：部署机的 `http://127.0.0.1:8100`（生产经反代，见部署指南 §4）
- 鉴权：所有 `/v1/*` 需请求头 `Authorization: Bearer <AGENT_BEARER_TOKEN>`；
  缺失/错误返回 `401`
- 内容类型：请求/响应均 `application/json`（除特别标注）

### 目标环境（env）

多数端点接受 `env`（body 字段或 query 参数）：要操作的业务环境
（prod/test/dev…）。缺省 = 服务端 `default_target_env`；服务端配了
`target_envs` 白名单时，不在列表内的值报 400。run、记忆、资产、闸门
全部按 env 分区。

### 错误格式

```json
{"detail": "人类可读原因"}                        // 一般错误
{"detail": "...", "error_code": "overloaded"}     // 429 并发打满
{"detail": "...", "error_code": "task_rejected"}  // 400 未知任务/闸门拒绝/终态冲突
```

| 状态码 | 含义 |
|---|---|
| 400 | 客户端错误（未知任务、闸门 deny、未知 env 等），重试无意义 |
| 401 | 未鉴权/令牌错 |
| 404 | 对象不存在 |
| 409 | 状态冲突（重复取消、审批已被处理、续跑非失败态等） |
| 422 | 参数校验失败（FastAPI 校验，`detail` 为字段错误列表） |
| 429 | 服务繁忙（并发打满），稍候重试 |

### run 状态机

`queued → running → success / failed / cancelled`；提交闸门命中
`require_approval` 时先落 `awaiting_approval`，批准 → `queued`，
拒绝 → `failed`。终态：`success / failed / cancelled`。

run 视图字段（GET 类端点返回）：`run_id, session_id, task_type,
task_version, role, role_version, domain, target_env, trigger_source,
caller, input, output, status, tokens, duration_ms, created_at`。

## 对话

### `POST /v1/chat`

同步问答（短任务）。

```json
{"server": "board", "role": "data_searcher", "question": "今日 GMV？",
 "session_id": "可选-续会话", "env": "可选"}
```

响应：200

```json
{"run_id": "a1b2c3...", "session_id": "board-fee-x1",
 "output": {"answer": "..."}, "note": "仅超时/待审批时出现"}
```

### `POST /v1/chat/stream`

SSE 流式问答（`text/event-stream`，每事件一行 `data: {json}`）：
请求体同上。事件序列：

| type | 时机 | 关键字段 |
|---|---|---|
| `run` | 首个事件 | `run_id`、`session_id` |
| `thought` / `tool_call` / `tool_result` / `note` | 执行过程逐步推送 | 见 SDK 指南事件表 |
| `final` | 终态 | `status`、`output` |
| `timeout` | 300s 未完成（run 仍在跑，拿 `run_id` 走 `/v1/tasks/{run_id}` 轮询） | `run_id` |

反代要点：`proxy_buffering off`、读超时 ≥ 300s。

## 任务（runs）

### `POST /v1/tasks`

异步提交任务。

- 请求头：`Idempotency-Key: <key>`（可选；24h 内同键重提返回首个 run，
  失败允许同键重提）
- Body：`{"task_type": "data-qa", "input": {...}, "caller": "来源标识",
  "role": "可选-覆盖默认角色", "env": "可选"}`

响应（三选一）：

```json
{"run_id": "...", "session_id": "...", "status": "queued", "dedup_hit": false, "target_env": "test"}
{"run_id": "...", "status": "dedup_hit", "dedup_hit": true}
{"run_id": "...", "status": "awaiting_approval", "approval_id": 12, "target_env": "test"}
```

### `GET /v1/tasks/{run_id}`

run 视图（字段见「通用约定」）。404 = 不存在。

### `GET /v1/runs`

列表（与 Viewer 同一查询实现）。

Query：`env, status, task, source, domain, q`（任务名/run id/问题关键词）,
`hours`（最近 N 小时）, `after`（上一页响应的 `next_cursor`，keyset
分页）, `limit`（默认 100，上限 500）。

响应：`{"runs": [...], "total": N, "next_cursor": "..."}`。

### `GET /v1/runs/{run_id}/events?after_seq=-1`

事件流增量拉取（观测进度）。响应：`{"run_id", "events": [{"seq","kind",
"payload","created_at"}...]}`；`after_seq` 传已收最大 seq。

### `POST /v1/runs/{run_id}/cancel`

Body：`{"by": "操作人"}`。取消运行中/排队中的 run；已终态 409。

### `POST /v1/runs/{run_id}/resume`

续跑失败/中断的 run（断点续跑，同 run_id）。非失败态 409。

### `POST /v1/runs/{run_id}/rerun`

失败/终止 → 断点续跑（同 id）；成功 → 同输入**新开** run。

## 审批

### `GET /v1/approvals?status=pending&limit=50`

`pending` = 待办收件箱；`approved`/`rejected`/空 = 已处理历史（带 total）。

### `POST /v1/approvals/{run_id}`

Body：`{"approved": true, "decided_by": "张三"}`。
并发审批被抢处理返回 409（回执不说谎）。批准提交闸门即启动执行。

## 反馈

### `POST /v1/feedback/{run_id}`

结论打分：Body `{"score": 1, "comment": ""}`（score 只收 +1/-1）。
回写该 run 沉淀的知识/案例评分，影响后续召回权重。

### `POST /v1/runs/{run_id}/steps/{seq}/feedback`

单步打分（时间线某一步的 👍👎）：Body 同上。

### `POST /v1/sessions/{session_id}/feedback`

纠正式反馈：Body `{"correction": "口径错了，应为...", "by": "张三"}`。
从该 session 最近一次 run 继承任务上下文重新判断（同 session 续上下文），
新结论沉淀时只取代上一次 run 的记忆，不误伤更早历史。
响应：`{"status": "correction_submitted", "run_id": "..."}`。

## Webhook（入站触发）

### `POST /v1/hooks/gitlab`

GitLab webhook（同样需 bearer）。只响应 `object_kind=deployment` 且
`status=success`；payload 带 `health_url` 时先做就绪探测，不过不触发。
取 `project.name / environment / ref` 触发前端冒烟任务（board 域包
`frontend-smoke`）；`environment` 即目标业务环境（命名需与
`target_envs` 一致）。

### `POST /v1/hooks/dagster`

Dagster run_failure_sensor 回调：`{"run_id", "asset_key", "error",
"env"?}`。报错先过域包规则库（命中即钉钉告警卡直接给结论，
`rule_resolved`），否则提交 `failure-analysis` 任务；episode 会话 id
按 `{asset}:{error_class}:{date}` 生成，同一故障周期续上下文。

## 记忆（知识条目）

知识记**事实**：口径、约束、环境特异信息。同 key 整替换（upsert 幂等），
覆盖前旧版自动进内容历史（可回滚）。

### `GET /v1/knowledge?env=&domain=&include_inactive=&include_content=`

清单。正文默认不扛（`include_content=true` 才带）；`include_inactive`
含已过期/被取代条目。

### `GET /v1/knowledge/search?q=...&domain=&env=`

检索试用：返回角色实际注入的 prompt 召回块 + 命中序（与线上 recall
同一实现，试用不计使用统计）。`q` 空 422。

### `POST /v1/knowledge?env=` → 201

写入/覆盖：`{"domain", "key", "content"}`。立即生效参与召回；
内容变化会留历史（source=manual）。

### `GET /v1/knowledge/{id}`

明细：整行 + `fresh`（code_ref 新鲜度）+ `chain`（演化链）+
`feedback`（来源 run 反馈）+ `usage`/`recent_hits`（真实召回用量）。

### `POST /v1/knowledge/{id}`

改正文：`{"content"}`（留历史，source=web-edit，同步重算向量）。

### `GET /v1/knowledge/{id}/history`

内容历史（新版本在前）：`{"history": [{"version","content","code_ref",
"source","created_at"}...]}`。

### `POST /v1/knowledge/{id}/history/{version}/restore`

回滚到指定历史版（当前内容先自动留档，回滚可逆；回滚后重算向量）。
版本不存在 404。

### `POST /v1/knowledge/{id}/expire` / `POST /v1/knowledge/{id}/restore`

软过期（退出召回，数据还在）/ 恢复生效。

### `GET /v1/knowledge/conflicts?env=&domain=`

疑似矛盾/重复对（向量余弦 ≥0.85 的生效条目对）。仲裁动作 =
对其中一条调 expire。无 pgvector 时返回空。

## 资产

资产记**方法**：procedure（方法）/script（脚本）/query（查询）/baseline
（基线）。文本类内容在 PG；文件类内容在资产目录包（PG 只存元数据）。

### `GET /v1/assets?env=&domain=&q=&kind=&state=&offset=0&limit=50`

列表：域/关键词/类型/状态（`on`/`off`）过滤 + offset 分页。
响应 `{"assets": [...], "total": N}`。

### `POST /v1/assets?env=` → 201

登记文本类资产：`{"domain","task?","kind","name","summary?","content"}`。
同 env+domain+task+kind+name 整替换（upsert 幂等，旧版进内容历史）。
文件类资产由运行中的 agent 用 save_asset 收编，不走此端点。

### `GET /v1/assets/{id}`

明细：整行 + `files`（文件清单，文件类）+ `revisions`（文件整替换
留档列表：`ts/files/bytes`）。

### `POST /v1/assets/{id}`

改说明/内容：`{"summary","content"}`（留内容历史，source=web-edit）。

### `GET /v1/assets/{id}/file?path=<相对路径>`

在线读文件类资产的单个文件（≤100KB 文本，`text/plain`）。

### `POST /v1/assets/{id}/rollback/{ts}`

**文件载体**回滚到留档版本 `ts`（当前版自动留档，可逆）。
响应：`{"ok": true, "restored": ts, "revisions": [...]}`。

### `GET /v1/assets/{id}/history` 与 `POST /v1/assets/{id}/history/{version}/restore`

**文本内容**（summary/content）历史与回滚，语义同知识条目；
文件载体不动（文件版本走上面的 `/rollback/{ts}`）。

### `POST /v1/assets/{id}/expire` / `POST /v1/assets/{id}/restore`

软过期（退出召回）/ 恢复。

## 定义管理（admin）

角色/任务/策略三类定义：**写即新版本、热生效**（不改库不用重启）；
历史全留，可 diff 可回滚。所有定义按**实例标签**（`settings.env`）存取，
与目标业务环境无关。

通用请求体（PUT 语义，POST 方法）：
`{"name", "definition": {...}, "updated_by": "操作人"}`；
定义不合法 422。保存响应带 `version`；若上一版本近 24h 有 run 在用，
附 `recent_runs_on_previous` 影响面提示。

| 端点 | 说明 |
|---|---|
| `POST /v1/admin/roles` | 保存角色（新版本）。启用 Langfuse 时写 Langfuse 为主、PG 写穿缓存；未启用只写 PG。内容不变不产生新版本 |
| `GET /v1/admin/roles` / `GET /v1/admin/roles/{name}` | 清单 / 单条（含活跃 version） |
| `GET /v1/admin/roles/{name}/history` | 版本历史 |
| `POST /v1/admin/roles/{name}/rollback/{version}` | 回滚 = 旧版内容成为新版本 |
| `POST /v1/admin/tasks` | 保存任务；定时任务随即重同步 Temporal Schedule（响应带 `schedule_resynced`） |
| `GET /v1/admin/tasks` / `GET /v1/admin/tasks/{name}` | 清单 / 单条 |
| `GET /v1/admin/tasks/{name}/history` + `POST .../rollback/{version}` | 历史 / 回滚（回滚也重同步 Schedule） |
| `POST /v1/admin/policies` | 保存提交闸门策略（正则 + order 的闸门链） |
| `GET /v1/admin/policies` / `GET /v1/admin/policies/{name}` | 清单 / 单条 |
| `GET /v1/admin/policies/{name}/history` + `POST .../rollback/{version}` | 历史 / 回滚 |

定义字段结构（`definition` 对象，字段均有默认值，最小定义只给必填项）：

**角色**（RoleDef）：

| 字段 | 类型 | 说明 |
|---|---|---|
| `description` | str | 角色一句话说明 |
| `domains` | list[str] | 可用业务域 |
| `tools` | list[str] | 工具白名单（bash/run_code/sql_query/save_asset…） |
| `prompt` | str | 系统提示词 |
| `extends` | str? | 继承的父角色（收敛式合并，不越界提权） |
| `prompt_append` | str | 继承时追加的提示词 |
| `interrupt_on` | dict? | 指定工具调用强制人工审批（如 `{"bash": true}`） |

**任务**（TaskDef）：

| 字段 | 类型 | 说明 |
|---|---|---|
| `role` | str | 单 agent 任务的角色 |
| `triggers` | list[str] | sdk/webhook/sensor/schedule/chat |
| `input_schema` | dict[str,str] | 输入字段声明 |
| `output_channel` | str | `caller`（不投递，默认）/ `dingtalk` / `http` |
| `output_callback` | str? | output_channel=http 时的回调地址 |
| `dedup_key` / `dedup_window_s` | str? / int | 业务去重键（支持 "a+b" 拼接输入字段）与窗口（默认 600s） |
| `schedule` / `schedule_input` | str? / dict | cron 表达式（Temporal Schedule）与定时固定输入 |
| `timeout_s` | int | 默认 300 |
| `env_gate` | list[str] | 空 = 所有目标环境启用；否则白名单 |
| `artifacts` / `handler` | dict? / str? | 任务形态：资产化任务图 / 内建处理器（默认单 agent 问答） |

**策略**（PolicyDef，提交闸门链的一环）：

| 字段 | 类型 | 说明 |
|---|---|---|
| `order` | int | 链内顺序，小的先判（默认 100） |
| `applies_to` / `envs` | list[str] | 空 = 所有任务 / 所有目标环境 |
| `match_regex` | str | 作用于 任务名+输入+question 的正则 |
| `action` | str | `deny`（拒绝）/ `require_approval`（挂起等审批） |
| `message` | str | 给调用方/审批人看的理由 |
| `enabled` | bool | 默认 true |

### 结果投递（output_channel）

任务终态后平台按 `output_channel` 投递结果（deliver_output，Temporal
重试 3 次，最终失败留 `deliver_failed` 事件、**不改变 run 状态**）：

- `caller`：不投递，调用方轮询 `GET /v1/tasks/{run_id}`
- `dingtalk`：钉钉通知（经中继）
- `http`：POST `output_callback`，回调体
  `{"run_id", "task_type", "status", "output"}`

## 速率与配额

- 无显式速率限制；同步对话路径受 `model.max_concurrency` 与在途上限
  保护，打满返回 429
- SSE 单连接上限 300s（超时后 run 继续在后台跑）
- 列表端点上限：`/v1/runs` limit≤500，`/v1/assets` limit≤200，
  `/v1/cases` limit≤500
